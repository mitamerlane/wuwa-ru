# Архитектура

Python 3.12, ядро на стандартной библиотеке + `cryptography`; интерфейс на PySide6
отделён от ядра. Один читатель архивов, одна база перевода, один фоновый исполнитель
для долгих операций — без параллельных хранилищ.

## Принципы

- **Игра — только два объекта.** Пишет в папку игры лишь `native_helper` по нажатию
  пользователя: наш PAK и одна строка в `MountLang_en.txt`. Всё остальное — чтение.
- **Ничего не угадываем.** Неизвестная версия клиента, незнакомое состояние Mount,
  несовпавший хеш — отказ с понятной причиной, а не попытка «как-нибудь».
- **Входные данные недоверенные.** Размеры ограничены, пути проверяются, архивы
  читаются потоково, загрузки сверяются по хешам и подписи.
- **Данные пользователя переносимы.** Всё лежит в папке программы (`Data`, `Backups`,
  `Exports`, …); миграция и резервные копии журналируются.
- **Ключи игры не нужны и не встраиваются.** Reader принимает ключ только извне;
  без ключа — `KEY_UNAVAILABLE`.

## Где что тестируется

`tests/` — ядро, формат, сборка пакета, подключение к синтетической «игре», установщик,
обновления; `gui_tests/` — окна в режиме Qt offscreen. Это функциональные проверки,
не ручная визуальная проверка и не запуск настоящей игры.
